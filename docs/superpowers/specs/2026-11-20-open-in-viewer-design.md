# «Открыть во вьюере» прямо со страницы трейса SignalFx

## Зачем

Сейчас посмотреть трейс во вьюере — это скачать N сегментов кнопкой в UI SignalFx (или `download_trace.py` с токеном),
сохранить файлы и перетащить их на страницу. Хотим: открыт трейс в SignalFx → один клик → подтверждение →
новая вкладка с вьюером на GitHub Pages, трейс уже загружен. Без Python и без API-токена.

## Цели / не цели / анти-цели

- Цель: один клик со страницы `…/#/apm/traces/<traceId>`; все сегменты склеиваются сами; локальная копия трейса.
- Не цель: делиться трейсом по ссылке с коллегами (нужно хранилище — отдельная задача).
- Анти-цель: трейс уходит куда-либо по сети, кроме самого SignalFx. GitHub Pages отдаёт только HTML вьюера.

## Подходы

- **A. Расширение Chrome + вьюер на GitHub** — выбран. Подтверждение, локальное хранение, история, вьюер один.
- B. Букмарклет — без установки, но нет хранилища и может упереться в CSP SignalFx.
- C. Расширение со встроенной копией вьюера — запасной вариант, если безопасность не пустит на GitHub.

Решено идти к A в два этапа: сначала отладить путь без расширения, потом обернуть.

## Протокол передачи трейса во вьюер (общий для обоих этапов)

Вьюер, открытый с `?from=sfx`:
1. не грузит демо `trace.json` (автозагрузка пропускается);
2. шлёт `{type: 'sfx-viewer-ready'}` в `window.opener` (этап 1) и в `window` (этап 2, слушает content script);
3. принимает `message` вида `{type: 'sfx-trace', name, data}` только от `window.opener` или `window`
   (`e.source`), `data` — то, что уже понимает `loadTrace` (`{traceId, spans}`), и вызывает `loadTrace(data, name)`.

Передача через `postMessage` (structured clone): десятки МБ проходят, в URL трейс не кладём.

## Этап 1 — отладка без расширения

- Правка `trace_viewer.html`: протокол выше. Тест в `test/viewer.test.mjs`: открыть `trace_viewer.html?from=sfx`,
  отправить `postMessage` с `trace.json` — спаны загружены, демо не грузилось.
- `extension/sfx-grab.js` — сниппет для консоли DevTools на странице трейса SignalFx:
  1. `traceId` из `location.hash`;
  2. запрос списка сегментов и каждого сегмента тем же способом, что и кнопка «Download Trace»
     (эндпоинт и авторизацию берём из вкладки Network; ориентир — `/v2/apm/trace/<id>/segments`
     и `/v2/apm/trace/<id>/<segment>`, как в `download_trace.py`);
  3. склейка + дедупликация по `spanId ?? id` (как `dedupe` в `download_trace.py`);
  4. копия `trace-<traceId>.json` в «Загрузки» (Blob + `<a download>`);
  5. `confirm('Открыть трейс … (N спанов) во вьюере?')` → `window.open(VIEWER_URL + '?from=sfx')` →
     ждём `sfx-viewer-ready` → `postMessage`.
- Готово, когда: на реальном трейсе вкладка вьюера открывается с ним, число спанов совпадает с SignalFx.

## Этап 2 — расширение (Manifest V3)

- Content script на домене SignalFx = логика `sfx-grab.js`; кнопка «Открыть во вьюере» на странице трейса.
- Трейс → `chrome.storage.local` (`unlimitedStorage`), последние ~10 трейсов; файл в «Загрузки» — опция.
- Подтверждение → `chrome.tabs.create(VIEWER_URL + '?from=sfx')`.
- Content script на `artycorp.github.io/sfx-trace-viewer/*`: ждёт `sfx-viewer-ready`, достаёт трейс из
  хранилища, `window.postMessage` в страницу. Вьюер не меняется — тот же протокол.
- Список доменов SignalFx (`host_permissions`) — из этапа 1.

## Открыто (решится на этапе 1)

- Какой эндпоинт и какую авторизацию использует UI SignalFx (cookie, заголовок `X-SF-Token` из сессии и т.п.).
- Домен SignalFx на работе: стандартный `app.<realm>.signalfx.com` или свой шлюз.
- Разрешена ли установка расширений на рабочем Chrome (влияет только на этап 2).

## На усмотрение исполнителя

- Вид кнопки и окна подтверждения, формат имени файла, размер истории.
