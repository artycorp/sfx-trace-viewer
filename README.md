# SFX Trace Viewer — просмотр куска длинного трейса SignalFx APM

Задача: часовой трейс → найти и разглядеть свою 12-секундную операцию.

**Онлайн-демо:** https://artycorp.github.io/sfx-trace-viewer/ — открывается на синтетическом
`trace.json`; свой трейс — перетащить файл на страницу (данные не покидают браузер).

## Установка на другой сервер

```bash
tar -xzf sfx-trace-viewer.tar.gz -C ~ && cd ~/sfx-trace-viewer
# зависимости: python3 (stdlib). UI — просто html-файл.
python3 make_synthetic_trace.py        # опционально: демо-трейс (час, ~2780 спанов, есть FE-спаны web-ui)
python3 -m http.server 8099            # открыть http://<host>:8099/trace_viewer.html
# trace_viewer.html работает и без сервера: открыть файл → перетащить trace.json
```

## Использование

### Вариант А (гарантированный): сегменты кнопкой из UI SignalFx

1. Открой трейс: `signalfx.com/#/apm/traces/<traceId>`
2. Trace Properties → «Download Trace (N Segments)» → сохрани N json-файлов
3. Склей и дедуплируй:

```bash
python3 download_trace.py --merge trace_segment_*.json -o trace.json
```

### Вариант Б: API (официальный Download APM traces API)

```bash
export SF_ACCESS_TOKEN="твой-org-API-токен"
python3 download_trace.py --trace-id <TRACE_ID> -o trace.json
# сам скачает ВСЕ сегменты трейса и склеит их
```

### Вариант В: прямо со страницы трейса (без Python и токена)

1. Открой трейс в SignalFx (`…/#/apm/traces/<traceId>`), DevTools → Console.
2. Вставь содержимое `extension/sfx-grab.js` и нажми Enter.
3. Скрипт под твоей сессией скачает все сегменты, склеит их, сохранит `trace-<traceId>.json` в «Загрузки»,
   спросит подтверждение и откроет вьюер на GitHub Pages — трейс передаётся из вкладки во вкладку, в сеть не уходит.

Свой шлюз API или заголовок авторизации — до вставки: `window.SFX_GRAB = { apiBase: 'https://…', headers: { 'X-SF-Token': '…' } }`.
Если браузер заблокировал окно — перетащи сохранённый файл на вьюер.

**То же расширением (без консоли):** `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» →
папка `extension/`. На странице трейса нажми иконку расширения — запустится тот же `sfx-grab.js`.
Права только `activeTab` + `scripting`: доступ к вкладке появляется лишь в момент клика. Сборка не нужна.
`SFX_GRAB` можно задать в консоли страницы до клика.

## Токены (3 способа, приоритет сверху вниз)

| Способ | Как | Когда удобен |
|---|---|---|
| 1. env | `export SF_ACCESS_TOKEN=…` (или `SPLUNK_ACCESS_TOKEN`) | разово в сессии, CI |
| 2. файл | `echo 'xxx' > .token && chmod 600 .token` (рядом со скриптом) | сервер/крон — файл в `.gitignore` |
| 3. флаг | `--token xxx` | разовый вызов |

Токен — **org access token с правом API** или session token
(SignalFx/Observability → Settings → Access Tokens). Уходит в заголовок `X-SF-Token`,
в командной строке в `ps` виден только у способа 3 — на сервере используй 1 или 2.

## Сервер SignalFx

```bash
# стандартный облачный: realm = кусок имени хоста app.<realm>.signalfx.com
# возможные: us0 us1 us2 eu0 eu1 ap0 ap1 …
python3 download_trace.py --trace-id <ID> --realm eu0        # или export SF_REALM=eu0

# свой шлюз/прокси/зеркало — полный base URL, перекрывает realm:
python3 download_trace.py --trace-id <ID> --api-base https://sfx-gw.corp.local
#                                                            или export SF_API_BASE=…
```

Без `--api-base` скрипт пробует `api.<realm>.observability.splunkcloud.com`,
затем legacy `api.<realm>.signalfx.com` и берёт первый живой.

## Просмотр

Открой `trace_viewer.html` → перетащи `trace.json` (можно несколько сегментов сразу —
склеятся в браузере) → на мини-карте всего трейса выдели окно мышью:
- протянуть — новое окно; тянуть за край — ширина; серединой — сдвиг; dblclick — зум ×4;
- «🔥 Плотная зона» — автопереход к самому насыщенному ~15с окну (часовой трейс
  открывается сразу в нём); кнопка «12s» — окно 12 секунд вокруг центра;
- waterfall только по окну: дерево по parentId, ось времени, клик → детали (tags + JSON);
- ▸/▾ у строки — свернуть/развернуть узел; «⊟ Свернуть» / «⊞ Развернуть» — весь трейс;
- «⤵ Провалиться» (в деталях спана) — выделенный спан становится корнем, окно = его
  длительности; хлебные крошки сверху: «▲ …» — подняться на уровень выше, `Esc`/«✕ выйти» —
  вернуться к прежнему окну;
- фильтры: поиск, min duration, только ошибки, вкл/выкл сервисов (чипы) + «⟲ все сервисы»
  для сброса; ошибки красным;
- поиск понимает условия по тегам (`tags` и `processTags`), через пробел = И:
  `span.kind=client`, `http.status_code>=500`, `http.url~partner`, `db.system` (тег есть),
  `!db.system` (нет), `key="a b"`; обычный текст ищется в сервисе/операции; подсказки
  ключей и значений — в автодополнении; у тегов в деталях кнопки `+`/`−` дописывают условие;
- «Ссылка на спан» в деталях копирует URL с `#span=<spanId>` — по нему трейс откроется
  сразу на этом спане (поддерево + путь до корня в крошках);
- **собственное время (self)** — длительность спана минус время детей (параллельные дети
  не считаются дважды): в деталях спана и в подсказке колонки «Длит.»;
- **«Критический путь»** (флажок) — цепочка спанов, задающая итоговую длительность
  (поддерево или корни окна): спаны пути обведены, остальные приглушены;
- **«Почему медленно»** — панель по поддереву (или по окну с фильтрами): критический путь
  по self, топ-10 спанов по self, группы «сервис · операция» (вызовы / сумма / self / max),
  метка `×N` при ≥10 одинаковых вызовах (N+1 / цикл); клик по группе — фильтр по ней;
- FE-спаны (`webjs` + `span.kind=client`) помечены значком; доля времени без бэкенда
  подсвечена штриховкой: жёлтая ≥40% и ≥150ms, красная ≥70% и ≥500ms, пунктир — бэкенда нет;
- «⬇ окно в JSON» — экспорт видимых спанов; клавиши `← →` сдвиг, `+ −` зум, `F` весь трейс, `H` плотная зона.

Как считается «плотная зона»: ось трейса делится на 1000 бакетов по времени, для каждого
считается число стартов спанов; по бакетам скользит окно шириной ~15 с, берётся позиция
с максимумом суммы. Считаются именно начала спанов (не длительности) — одна длинная
операция без детей зону не «нагреет».

Понимает формат Download APM traces API (`startTime` ISO + `durationMicros`)
и zipkin-подобный (`id`/`timestamp` в мс/мкс/нс — определяется по величине).

## Файлы

- `trace_viewer.html` — оффлайн UI (открывается без сервера)
- `index.html` — редирект на `trace_viewer.html` для GitHub Pages (сохраняет `#span=…`)
- `test/viewer.test.mjs` — браузерные тесты на демо-трейсе (и поддельном API SignalFx для `sfx-grab.js`)
- `extension/sfx-grab.js` — выгрузка трейса со страницы SignalFx во вьюер (сниппет для консоли, будущее расширение)
- `download_trace.py` — загрузка через API / merge сегментов из UI
- `make_synthetic_trace.py` — генератор демо-трейса (создаёт `trace.json`)
- `trace.json` — синтетический демо-трейс (час, плотная 12s-операция в 14:40, вызвана из браузера web-ui — примеры подсветки FE/backend)
- `.token` — место для токена на сервере (не коммитится, в `.gitignore`)

## Ограничения

- Сегменты API ограничены 8 МБ на скачивание (лимит SignalFx).
- Вьюер рендерит 1500 строк за раз (кнопка «показать ещё»); для тысяч спанов
  сужай окно или включай фильтр по длительности.
